Este guia apresenta como integrar sistemas externos ao ERP via API REST.

## Visão Geral da API

A API do ERP permite:
- Consultar e cadastrar produtos
- Consultar e criar pedigos
- Consultar clientes
- Consultar estoque
- Integrar com sistemas externos

## URLs de Acesso

| Ambiente | URL Base |
|----------|----------|
| Produção | `https://erp.suaempresa.com.br/api/v1` |
| Homologação | `https://hom.erp.suaempresa.com.br/api/v1` |

## Autenticação

### Token de Acesso

1. Acesse **Extras → API → Tokens**
2. Clique em "Novo Token"
3. Configure:
   - Nome do token
   - Permissões
   - Data de expiração
4. Copie o token (mostrado apenas uma vez)

### Usar o Token

Inclua o token no cabeçalho de cada requisição:

```
Authorization: Bearer SEU_TOKEN_AQUI
```

### Exemplo com cURL

```bash
curl -X GET "https://erp.suaempresa.com.br/api/v1/produtos" \
  -H "Authorization: Bearer seu_token_aqui" \
  -H "Content-Type: application/json"
```

## Endpoints Disponíveis

### Produtos

| Método | Endpoint | Descrição |
|--------|----------|-----------|
| `GET` | `/produtos` | Listar produtos |
| `GET` | `/produtos/:id` | Buscar produto por ID |
| `POST` | `/produtos` | Criar produto |
| `PUT` | `/produtos/:id` | Atualizar produto |
| `DELETE` | `/produtos/:id` | Excluir produto |

### Clientes

| Método | Endpoint | Descrição |
|--------|----------|-----------|
| `GET` | `/clientes` | Listar clientes |
| `GET` | `/clientes/:id` | Buscar cliente por ID |
| `POST` | `/clientes` | Criar cliente |
| `PUT` | `/clientes/:id` | Atualizar cliente |
| `DELETE` | `/clientes/:id` | Excluir cliente |

### Pedidos

| Método | Endpoint | Descrição |
|--------|----------|-----------|
| `GET` | `/pedidos` | Listar pedidos |
| `GET` | `/pedidos/:id` | Buscar pedido por ID |
| `POST` | `/pedidos` | Criar pedido |
| `PUT` | `/pedidos/:id` | Atualizar pedido |
| `PUT` | `/pedidos/:id/status` | Atualizar status |

### Estoque

| Método | Endpoint | Descrição |
|--------|----------|-----------|
| `GET` | `/estoque` | Consultar estoque |
| `GET` | `/estoque/:sku` | Estoque por SKU |
| `POST` | `/estoque/ajuste` | Ajustar estoque |

## Exemplos de Requisição

### Listar Produtos

```json
GET /api/v1/produtos

Response:
{
  "data": [
    {
      "id": 1,
      "sku": "WID001",
      "nome": "Widget A",
      "preco": 50.00,
      "estoque": 100
    }
  ],
  "meta": {
    "total": 1,
    "page": 1,
    "per_page": 20
  }
}
```

### Criar Produto

```json
POST /api/v1/produtos

{
  "sku": "WID002",
  "nome": "Widget B",
  "descricao": "Descrição do Widget B",
  "preco_custo": 25.00,
  "preco_venda": 50.00,
  "estoque": 50,
  "categoria": "Widgets"
}

Response:
{
  "data": {
    "id": 2,
    "sku": "WID002",
    "nome": "Widget B",
    "created_at": "2026-08-01T10:00:00Z"
  }
}
```

### Criar Pedido

```json
POST /api/v1/pedidos

{
  "cliente_id": 1,
  "itens": [
    {
      "produto_id": 1,
      "quantidade": 2,
      "preco_unitario": 50.00
    }
  ],
  "data_entrega": "2026-08-10",
  "condicao_pagamento": "30_dias"
}

Response:
{
  "data": {
    "id": 1234,
    "status": "pendente",
    "total": 100.00
  }
}
```

## Paginação

### Parâmetros

| Parâmetro | Padrão | Descrição |
|-----------|--------|-----------|
| `page` | 1 | Página atual |
| `per_page` | 20 | Itens por página |

### Exemplo

```
GET /api/v1/produtos?page=2&per_page=10
```

### Resposta

```json
{
  "data": [...],
  "meta": {
    "total": 100,
    "page": 2,
    "per_page": 10,
    "total_pages": 10
  }
}
```

## Filtros

### Filtrar por Status

```
GET /api/v1/pedidos?status=aprovado
```

### Filtrar por Data

```
GET /api/v1/pedidos?data_inicio=2026-08-01&data_fim=2026-08-31
```

### Filtrar por Campo

```
GET /api/v1/produtos?categoria=widgets&estoque_minimo=10
```

## Erros da API

### Códigos de Erro

| Código | Descrição |
|--------|-----------|
| `200` | Sucesso |
| `201` | Criado com sucesso |
| `400` | Requisição inválida |
| `401` | Não autenticado |
| `403` | Sem permissão |
| `404` | Não encontrado |
| `422` | Erro de validação |
| `500` | Erro interno |

### Formato do Erro

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Dados inválidos",
    "details": {
      "sku": "SKU já existe"
    }
  }
}
```

## Webhooks

### Configurar Webhook

1. Acesse **Extras → API → Webhooks**
2. Clique em "Novo Webhook"
3. Configure:
   - URL de destino
   - Eventos desejados
   - Secret (para validação)
4. Ative

### Eventos Disponíveis

| Evento | Descrição |
|--------|-----------|
| `pedido.criado` | Novo pedido |
| `pedido.aprovado` | Pedido aprovado |
| `pedido.enviado` | Pedido enviado |
| `estoque.baixo` | Estoque abaixo do mínimo |
| `produto.cadastrado` | Novo produto |

### Payload do Webhook

```json
{
  "event": "pedido.criado",
  "data": {
    "id": 1234,
    "cliente_id": 1,
    "total": 100.00
  },
  "timestamp": "2026-08-01T10:00:00Z"
}
```

## Boas Práticas

:::tip[Dica]
Use tokens com permissões mínimas necessárias.
:::

:::tip[Dica]
Armazene tokens de forma segura, nunca no código fonte.
:::

:::tip[Dica"
Implemente tratamento de erros robusto.
:::

:::caution[Importante]
Nunca exponha tokens em repositórios públicos.
:::

## Limites de Uso

| Recurso | Limite |
|---------|--------|
| Requisições/minuto | 100 |
| Requisições/dia | 10.000 |
| Tamanho do payload | 1 MB |
| Timeout | 30 segundos |

## Dicas de Integração

1. **Cache** - Implemente cache para dados que não mudam frequentemente
2. **Retry** - Implemente retry automático em caso de falha
3. **Logs** - Registre todas as requisições para debug
4. **Validação** - Valide dados antes de enviar
5. **Tratamento de erros** - Trate todos os códigos de erro
